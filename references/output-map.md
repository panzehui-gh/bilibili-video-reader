# 产物与证据入口

先读入口返回的 `summary.json`，当前 `schema_version` 是 `2`。本次运行位置和每个视频项的绝对路径由 manifest 指定，不能假设旧版 `output/bilibili/` 或之前聊天目录仍存在。

## 读取顺序

1. 查看请求的模式、源链接/本地素材、关注时刻，以及 `items` 中每项的 `status` 与错误。每项 `stages` 的 `metadata`、`download`、`subtitles`、`visual`、`speech`、`sound` 各自含 `status`；未请求、失败和成功应分别判断。
2. 查看视频元数据和探测到的时长。时长未知或仅取得局部时，记录实际范围。
3. 根据任务找到平台字幕、原声 ASR、画面或声音产物。缺失项是未知或未执行，不是空内容。
4. 打开相关图像，核对文字产物和时间范围，最后进行跨模态解释。

## 主要产物的含义

| 产物/语义 | 如何使用 |
| --- | --- |
| `summary.json` | 本次入口、每项 `status`、阶段结果、错误及产物位置；成功、部分完成、失败应按实际状态报告 |
| `metadata_path` | 标题、作者、时长和源信息；简介只能说明页面声称的内容 |
| `media_path` | 保留的本次视频素材，可在后续通过 `-SourceMedia` 复用 |
| `subtitle_transcript_path` | 仅平台字幕文本，可能来自投稿者或平台自动字幕；不能当作独立原声验证 |
| `speech_transcript_path` | 仅原声 ASR 文本，本地模型直接从音轨生成，独立于平台字幕 |
| `speech_result_path` | 原声识别的 `segments`、`words`、`language` 等；时间和自动语言判断仍可能有误 |
| `frames` | 数组，每项含 `path`、`timestamp_seconds`、`timestamp_label`、`origin`；必须实际查看图片后才能描述画面 |
| `frame_manifest_path` | 单独保存的帧清单，供检查范围和追加局部核对 |
| `scene_candidates` | 带 `timestamp_seconds` 的自动变化候选；不等于已经确认的转场、场景或功能事件 |
| `sound_summary` | 音频模块返回的 summary，包含声音分析完成情况及产物位置 |
| `audio_timeline_path` | 带时间位置的声学结果与声音分析时间线 |
| `event_tags_path` | 本地事件分类的候选标签及分数；不是已确认事实 |
| `transient_candidates_path` | 声学瞬态候选，不能一律称为点击、鼓点或 UI 音效 |

原声音轨从本次 `media_path` 提取；立体声音轨用于声学分析，16 kHz 单声道副本用于模型输入，位置按阶段返回值解析。文件缺失、路径为空或阶段失败时不补造内容。多 P 视频或多个视频项分别读取，不能把第一项的结果推广到其余项。

## 部分完成时

- 取得字幕但未取得音轨：可总结字幕，不能报告已核查原声或音乐。
- 取得画面但无 ASR：可描述实际看到的帧，不能把可见文字当成口述。
- ASR 无分段：查看状态、音轨与声音结果，区分执行失败、没有明显语音和模型漏识别；不能据此断言绝对无人说话。
- 声音分类失败但音轨存在：仍可报告已完成的声学分析；不编造未得到的标签。
- 只得到部分帧或关注窗口：限定结论范围；有必要时补取相关时间段。
- 访问被拒、登录或风控失败：引用实际错误，不尝试自动提取 Cookie。若已有本地源文件，复用它而不是重复下载。
- 本地 runtime 缺失：说明准确缺项，不自动转云。原始错误和已生成的证据应保留在本次输出中。

## 对用户交付

只选择解释问题所需的时间线、关键帧或转写片段。清楚区分“画面中可见”“本地 ASR 识别为”“分类模型倾向于”和分析推断。长篇机器日志与全部中间文件不必塞进回答；需要交付文件时遵循当前工作区的输出目录规则。
