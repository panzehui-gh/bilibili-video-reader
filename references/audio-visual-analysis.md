# 原声、音乐与画面对齐

用于用户询问音乐、提示音、非语音声音、原声讲解或音画配合时。平台字幕、原声 ASR、声音分类和可见画面是不同证据，分别核查后再组合。

## 本地音频流程

单入口 `run_bilibili.ps1` 负责调度。单独诊断音频模块时，接口是位置参数 WAV：

```text
scripts/analyze_audio.py original_stereo.wav --event-wav audio16k.wav --out-dir audio-results --model-dir runtime/yamnet
```

不要使用不存在的 `--wav` 参数。模块也可由入口导入：

```python
analyze_audio(input_wav, *, out_dir, model_dir, event_wav=None,
              window_seconds=1.0, boundaries=None, save_metrics=False)
```

`input_wav` 是原始分析音轨；`event_wav` 是供事件模型使用的 16 kHz 单声道副本。输出 summary dict 与落盘文件共同记录完成状态和产物。以实际返回字段为准，失败时不要用旧文件冒充本次结果。

## 原声与 ASR

- 对原声音轨进行本地 ASR，不把平台字幕当作 ASR 的替代输入或转写答案。
- 默认自动识别语言；只有明确依据时设置 `-SpeechLanguage`。记录模型判断的语言及不确定性。
- 原声 ASR 是模型识别结果，不等同人工逐字听校。音乐、人声采样、歌声、合成声音和噪声都可能导致漏词或幻觉。
- 若进行不启用 VAD 的复核，保留首轮和复核两份结果；不能静默覆盖，也不能拿画面词替换两个版本中的不确定内容。
- 若 ASR 与字幕冲突，保留来源和对应时段。无法核实的词标成不确定，不根据画面内容悄悄补全。
- 没有可靠语音分段时，可说明“本次 ASR 未检出可靠讲解”，不要直接断言视频没有任何人声。

## 非语音分类与声学指标

本地 YAMNet 使用 16 kHz、单声道、`float32` 波形，数值范围约 `[-1, 1]`。图内包含音频特征提取；分类输出是多标签分数，不是互斥概率，不能再次 softmax。

分类时间窗约 0.96 秒、步长 0.48 秒；实际 STFT 覆盖略长，末尾可能补零。使用产物中的时间戳和有效范围，不把分类窗口中心当成某个声音精确起始时刻。

可用分数寻找需要复核的区间，例如音乐、人声、电子音或噪声。它们不能单独确认曲名、乐器、配器、音效来源、作者意图或音乐情绪。混音中的短促提示声可能被背景音乐掩盖，也可能让模型误判。

波形、能量、频谱和瞬态用于描述声学变化，例如“这里能量升高”“这一段出现窄带持续成分”。仅有峰值不证明是点击、鼓点、警报或 UI 音效。不要从这些图形虚构主观听感。

## 与画面对齐

1. 确认音频和帧时间戳使用同一个 `media_path`、起点与偏移。局部剪辑或 `FocusSeconds` 结果不可直接混用绝对时间和局部时间。
2. 从声学变化和 `scene_candidates` 中选择与问题有关的时刻，实际打开该时刻前后的帧。
3. 分别记录声学观察与视觉观察，再说明二者的时间关系。允许描述“画面切换附近出现能量峰值”；没有更多证据时，不把它写成“点击按钮触发了提示音”。
4. 若需要精确同步判断，补取更密的局部帧或缩小声学观察区间；不要用约一秒的模型分类窗口证明毫秒级同步。
5. 报告具体的已查范围、支持解释的时间点，以及没有核实的部分。自动变化候选和分类分数不能代替实际看图。

实用的回答组织是：视频在相关时间点做了什么、声音数据在同一时段如何变化、两者可能怎样配合。证据不足时保留解释的条件，不为了写出完整故事而补造听到的内容。

## 运行边界

运行环境、模型和解码工具来自 skill 的 `runtime`。全流程默认本地，不把用户音轨发送给外部推理服务；模型缺失、访问受限或某个分析阶段失败时，报告该阶段和可用证据。只有用户明确要求时，才另行采用云 API。
